# CLAUDE.md — pve-agent-scripts

## What This Is

Non-interactive, agent-friendly fork of [community-scripts/ProxmoxVE](https://github.com/community-scripts/ProxmoxVE). Strips all whiptail/dialog interactive prompts from 509 LXC container creation scripts and replaces them with env vars and a CLI wrapper. Synced with upstream (679 commits merged). Tested on Proxmox 9.1.5.

- Repo: `smashingtags/pve-agent-scripts`
- Owner: Michael (smashingtags)
- License: MIT
- Upstream: community-scripts/ProxmoxVE

## Architecture

```
pve-agent              (Python CLI — list/search/info/create/update/catalog)
  |
  v
catalog.json           (machine-readable index of 509 apps, generated by tools/convert.py)
  |
  v
ct/*.sh                (510 container scripts — UNTOUCHED upstream scripts, 509 after dedup)
  |                     Each sources build.func from GitHub on line 2.
  |                     pve-agent patches this at runtime by:
  |                       1. Sourcing misc/agent-build.func instead
  |                       2. Using sed to strip the upstream source line
  |                       3. eval'ing the rest of the script body
  v
misc/agent-build.func  (non-interactive build.func replacement — env vars only)
  |
  v
install/*.sh           (501 install scripts — UNTOUCHED, run inside containers)
```

## EOS Migration — Three-Repo Setup

The EOS-rebranded version uses three repos:

| Repo | Visibility | Role |
|------|-----------|------|
| `smashingtags/pve-agent-scripts` | Public (MIT) | Upstream sync point. Merges from community-scripts, stays PVE-native. |
| `smashingtags/eightly-os` | Private | Has `tools/eos-agent/transform.py` — reads catalog.json from this repo, rewrites PVE commands to native LXC (`lxc-create`, `lxc-start`, `lxc-attach`), rebrands `PVE_*` env vars to `EOS_*`. |
| `smashingtags/eos-agent-scripts` | Private | Generated output — 509 EOS-native LXC app scripts. Don't edit directly; regenerate via transform.py. |

## Rules

- ct/*.sh and install/*.sh are upstream scripts. Don't modify them unless fixing agent-specific integration.
- agent-build.func is the core agent logic. Changes here affect all 509 apps.
- tools/convert.py generates catalog.json, pve-agent, and agent-build.func. If you edit any of those directly, convert.py will overwrite them on next run. Edit convert.py instead.
- Shell scripts target Linux (Proxmox VE host). No macOS compatibility needed.
- No Co-Authored-By on commits.
- Test changes on Proxmox 8 or 9 before calling them done.

## Build & Test

```bash
# Regenerate catalog from ct/*.sh (also overwrites pve-agent and agent-build.func)
python3 tools/convert.py

# Verify CLI works
./pve-agent list
./pve-agent search docker
./pve-agent info adguard
./pve-agent create adguard --dry-run

# Verify on Proxmox host (SSH to a PVE node first)
./pve-agent create adguard --dry-run --verbose
```

## Known Constraints

- `tools/convert.py` embeds pve-agent, agent-build.func, and README as string literals — monolithic but functional. Overwrites those files on every run.
- 33 ct scripts use heredocs, which need careful handling in the eval wrapper
- 57 install scripts have YES/NO prompts auto-declined via empty stdin pipe
- Only 1/16 VM scripts (docker-vm.sh) converted to agent mode
- turnkey.sh is unconverted and not referenced by pve-agent
- EOS-rebranded version maintained separately in private eos-agent-scripts repo (generated by transform.py in eightly-os)
- Tested on Proxmox 8.x and 9.1.5 (AdGuard deployed successfully on 9.1.5)
- catalog.json deduplication handled by convert.py (510 ct scripts → 509 unique apps)
