# CLAUDE.md — pve-agent-scripts

## What This Is

Non-interactive, agent-friendly fork of [community-scripts/ProxmoxVE](https://github.com/community-scripts/ProxmoxVE). Strips all whiptail/dialog interactive prompts from ~466 LXC container creation scripts and replaces them with env vars and a CLI wrapper.

- Repo: `smashingtags/pve-agent-scripts`
- Owner: Michael (smashingtags)
- License: MIT
- Upstream: community-scripts/ProxmoxVE

## Architecture

```
pve-agent              (Python CLI — list/search/info/create/update/catalog)
  |
  v
catalog.json           (machine-readable index of 465+ apps, generated by tools/convert.py)
  |
  v
ct/*.sh                (465 container scripts — UNTOUCHED upstream scripts)
  |                     Each sources build.func from GitHub on line 2.
  |                     pve-agent patches this at runtime by:
  |                       1. Sourcing misc/agent-build.func instead
  |                       2. Using sed to strip the upstream source line
  |                       3. eval'ing the rest of the script body
  v
misc/agent-build.func  (non-interactive build.func replacement — env vars only)
  |
  v
install/*.sh           (455 install scripts — UNTOUCHED, run inside containers)
```

## Key Files

| File | Lines | Role |
|------|-------|------|
| `pve-agent` | ~360 | Python CLI entry point |
| `misc/agent-build.func` | ~700 | Non-interactive build functions (bash) |
| `catalog.json` | ~208KB | Generated app index (JSON) |
| `tools/convert.py` | ~1400 | Master generator — produces catalog.json, agent-build.func, pve-agent, README |
| `misc/build.func` | ~5800 | Upstream interactive build.func (reference only) |
| `misc/core.func` | ~1700 | Core utilities sourced by agent-build.func |

## EOS Migration Path

This repo is PVE-specific but designed for eventual EOS (Eight.ly OS) compatibility:
- All `PVE_*` env vars map to container config (rename prefix for EOS)
- All `pct`/`pvesh`/`pvesm`/`pveam` calls are Proxmox-specific (abstract for EOS)
- The `ct/*.sh` scripts are upstream and won't change — the abstraction layer is entirely in `agent-build.func`

## EOS Migration

The EOS-rebranded version of these scripts lives in the private `smashingtags/eightly-os` repo under `tools/eos-agent/`. A build tool there reads `catalog.json` from this repo, rewrites PVE commands to native LXC (`lxc-create`, `lxc-start`, `lxc-attach`), and rebrands env vars from `PVE_*` to `EOS_*`. This repo stays as the upstream sync point — EOS repo has the transformed output.

## Rules

- ct/*.sh and install/*.sh are upstream scripts. Don't modify them unless fixing agent-specific integration.
- agent-build.func is the core agent logic. Changes here affect all 464 apps.
- tools/convert.py generates catalog.json. If you edit catalog.json directly, convert.py will overwrite it.
- tools/eos_transformer.py generates eos-templates/. The image map in that file is the source of truth for PVE→Docker mapping.
- Shell scripts target Linux (Proxmox VE host). No macOS compatibility needed.
- No Co-Authored-By on commits.
- Test changes on Proxmox 8 before calling them done.

## Build & Test

```bash
# Regenerate catalog from ct/*.sh
python3 tools/convert.py

# Verify CLI works
./pve-agent list
./pve-agent search docker
./pve-agent info adguard
./pve-agent create adguard --dry-run

# Generate EOS templates
python3 tools/eos_transformer.py

# Verify on Proxmox host (SSH to a PVE node first)
./pve-agent create adguard --dry-run --verbose
```

## Known Constraints

- `tools/convert.py` embeds pve-agent, agent-build.func, and README as string literals — monolithic but functional
- 33 ct scripts use heredocs, which need careful handling in the eval wrapper
- 57 install scripts have YES/NO prompts auto-declined via empty stdin pipe
- Only 1/16 VM scripts (docker-vm.sh) converted to agent mode
- turnkey.sh is unconverted and not referenced by pve-agent
- EOS-rebranded version maintained separately in private eightly-os repo
